# Release preparation — 24 October 2026

The confirmed code findings from the stable-readiness audit are addressed by the
previous security/interaction changes, durable economy PR #131 and the service
commerce follow-up. No point coordinates were placed during this work.

The service follow-up makes bar stock, mixing and serving, media sales, and fuel-can
purchases/refills durable with their inventory changes. Accepted bar tabs are
created in the handover transaction. Staff authority and proximity are rechecked
following inventory save fences. Media caps and scene history persist across restart;
a locked newsroom row protects concurrent sales.

Automated qualification: 6,719 Lua checks, 61 audit scripts, 360 real InnoDB
rollback/replay/concurrency checks, Lua syntax, sandbox globals and four UI lifecycle
scripts. The SQL qualification uses isolated test data, never production wallets.
The full client budget measurement is recorded in the pull request.

## Remaining live qualification

Before tagging a stable release, test with two actual clients on game build 25000
and Open77 2.50.0+op77.152:

- Login, character switching, disconnect/reconnect and persisted state.
- Dense target menus and interactions, watching the client instruction budget.
- Purchases, peer trades, stashes, crafting, invoices and service billing, including
  refusal, full inventory, interruption and reconnect cases.
- Compatible dual-wield pairs, the friendly Chao refusal, clothing/cyberware
  reapplication and their documented visibility between players.
- Native fuel transfer/consumption, cans, medical/drug effects and physical doors.
  Database tests do not validate effects inside the game engine. Physical locks
  use the client backend; sensitive actions retain independent server checks.

Point placement remains intentionally outside this change. Fivemanage upload and
catalogue access need a real operator API key; no authenticated CDN end-to-end
verification is claimed without it.
